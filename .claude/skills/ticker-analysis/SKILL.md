# Ticker Analysis — Сводный анализ одной акции

## Назначение

Этот скил выполняет полный, end-to-end разбор **одного тикера** и формирует пакет файлов, который можно использовать как готовое торговое решение: новости, фундаментал, техника и итоговый отчёт с конкретными точками входа. Дополнительно — **автоматически создаёт алерты в TradingView Desktop** на ключевые уровни приоритетного сценария (Trigger / Stop / T1 / T2 / T3), чтобы пользователь получил уведомление, как только цена дойдёт до точки действия.

Скил **координирует** уже существующие специализированные скилы — ничего не дублирует, а вызывает их методологии и собирает результаты в единую структуру.

## Когда триггериться

- «проанализируй TICKER», «сделай аналитику по TICKER», «дай полный разбор TICKER»
- «стоит ли покупать TICKER», «что делать с TICKER», «разбор тикера X»
- «analyze TICKER», «full analysis of TICKER», «give me a report on TICKER»
- любой запрос, где пользователь хочет ОДНОВРЕМЕННО новости + фундаментал + технику по одной бумаге

Не триггериться, если запрос узкий: только новости / только техника / только сравнение нескольких тикеров — в этих случаях работают точечные скилы (`market-news-analyst`, `technical-analyst`, `us-stock-analysis` для compare).

## Структура результата

Всё сохраняется в `results/analysys/TICKER/YYYY-MM-DD/`, где TICKER — это тикер в верхнем регистре без префикса биржи (BSX, не NYSE:BSX), а дата — текущая дата из контекста сессии.

```
results/analysys/TICKER/YYYY-MM-DD/
├── news.md           # новостной фон, ранжированный по импакту
├── fundamental.md    # финансы, мультипликаторы, оценка vs peers
├── technical.md      # weekly + daily ТА (тренд, уровни, индикаторы)
├── report.md         # сводный отчёт с точками входа (главный файл)
├── TICKER_daily.png  # скриншот дневного графика с индикаторами
└── TICKER_weekly.png # скриншот недельного графика с индикаторами
```

Эта структура — реальный шаблон, уже используемый в репо (см. `results/analysys/BSX/2026-05-15/`). Следуй ему.

Дополнительно: финальный сигнал (BUY/HOLD/SELL + entry/stop) дозаписывается в общий журнал `results/analysis/signals.md` — см. раздел «Сохранение сигнала». В дополнение к файлам, в TradingView Desktop создаются 4–5 алертов на Trigger / Stop / T1 / T2 / T3 приоритетного сценария — см. раздел «Создание алертов».

## Алгоритм работы

### Шаг 0. Подготовка

1. Извлеки тикер из запроса. Нормализуй: `BSX`, не `bsx`/`Boston Scientific`/`NYSE:BSX`.
2. Возьми дату из системного контекста (`Today's date is YYYY-MM-DD` в claudeMd). Это `DATE`.
3. Создай каталог: `mkdir -p results/analysys/TICKER/DATE`.
4. Создай задачи через TaskCreate (3 параллельные ветки + сводка + алерты):
   - Сбор новостей
   - Фундаментальный анализ
   - Технический анализ (TradingView)
   - Сводный отчёт + точки входа
   - Создание алертов в TradingView на ключевые уровни приоритетного сценария

### Шаг 1. Новостной анализ → `news.md`

Делегируй методологию скилу **market-news-analyst**, но сузь его до конкретного тикера и периода 10–14 дней.

Используй `WebSearch` и `WebFetch`. Параллельно ищи:
- `"TICKER earnings"` за последний квартал
- `"TICKER news last 10 days"` — общие события
- `"TICKER FDA/SEC/lawsuit/recall/M&A"` — корпоративные катализаторы
- `"TICKER analyst ratings upgrade downgrade"` — sell-side движения
- секторные / макро катализаторы, если они применимы (FOMC, тарифы, отраслевые регуляции)

Если новостной поток объёмный (мегакап на отчётах) — запусти подагент `general-purpose` или `Explore` для параллельного сбора через `WebSearch`. Иначе достаточно 3–5 прямых `WebSearch` вызовов.

**Формат `news.md`** (английский — это норма market-news-analyst):

```markdown
# TICKER News Analysis — START_DATE to END_DATE

**Ticker:** Full Company Name (EXCHANGE: TICKER) | **Price:** ~$XX.XX | **Period:** Last N days

## Top News Items (Ranked by Market Impact)

| # | Date | Event | Sentiment | Impact |
|---|------|-------|-----------|--------|
| 1 | ... | ... | Bullish/Bearish/Neutral | Severe/Major/Moderate/Minor |

## Net Sentiment: POSITIVE/NEGATIVE/MIXED (short-term)

[2–4 предложения о том, что сейчас рынок отыгрывает]

## Key Catalysts & Risks (Next 1–4 Weeks)

**Risks (Bearish):**
- ...

**Catalysts (Bullish):**
- ...

**Trade view:** [одна строка — как новости влияют на ближайшее поведение]
```

Ранжируй по impact score методологии market-news-analyst (см. `.claude/skills/market-news-analyst/SKILL.md` §3) — но не переусердствуй с скорингом для одной бумаги, достаточно 4–6 ключевых событий.

### Шаг 2. Фундаментальный анализ → `fundamental.md`

Используй методологию скила **us-stock-analysis** (раздел «Fundamental Analysis»). Все данные тащи через `WebSearch`/`WebFetch` (Yahoo Finance, Seeking Alpha, инвесторский раздел самой компании, последний 10-Q/10-K).

Что собрать:
- последний квартал: выручка, EPS, маржа, гайденс — сравни с консенсусом и YoY
- сегменты бизнеса (драйверы и слабые места)
- баланс: долг, кэш, FCF, interest coverage, D/E
- оценка: Fwd P/E, EV/EBITDA, PEG, P/B; сравнение с 2–4 ключевыми peers
- риски (исковая нагрузка, регуляторика, ключевые продукты)

**Формат `fundamental.md`** (русский — согласно `.claude/rules/language.md`):

```markdown
# Company Name (TICKER) — Фундаментальный анализ

**Дата:** YYYY-MM-DD
**Текущая цена:** ~$XX.XX
**Капитализация:** ~$XB

## 1. Результаты последнего квартала (отчёт от DATE)

[Таблица с метриками: Выручка / EPS / маржа / FCF — Факт / Конс. / Y/Y]

[1–2 предложения о beat/miss и реакции рынка]

## 2. Сегменты — драйверы

[Разбивка по сегментам с динамикой]

## 3. Маржа, FCF, долг

[Operating margin, FCF, debt levels, ratios]

## 4. Оценка vs пиры

[Таблица: Fwd P/E / EV/EBITDA / Рост выручки / Комментарий]

## 5. Риски

[Bullet-list ключевых рисков]

## Вердикт

[Бычий / медвежий / нейтральный + 2–3 предложения почему]
```

### Шаг 3. Технический анализ → `technical.md` + скриншоты

Используй методологию **technical-analyst** + **chart-analysis** + живой график через **tradingview-mcp**. Это самая ценная часть — потому что у нас есть прямой доступ к TradingView Desktop.

Алгоритм:

1. **Переключи символ:** `mcp__tradingview__chart_set_symbol` с тикером (можно с биржей, например `NYSE:BSX`).
2. **Сначала Weekly:**
   - `mcp__tradingview__chart_set_timeframe` → `"W"`
   - Добавь индикаторы через `chart_manage_indicator` (полные имена!): `"Moving Average Exponential"` ×3 (20/50/200), `"Relative Strength Index"`, `"MACD"`, `"Stochastic"`, `"Volume"`. Если они уже есть — `chart_get_state` это покажет; не дублируй.
   - `data_get_study_values` → текущие значения всех индикаторов
   - `data_get_ohlcv` с `summary: true` + `count: 30` для последних 30 недель
   - `quote_get` → последняя цена
   - `mcp__tradingview__capture_screenshot` с `region: "chart"` → сохрани как `TICKER_weekly.png` (перенеси / переименуй из `screenshots/` в каталог отчёта)
3. **Затем Daily:**
   - `chart_set_timeframe` → `"D"`
   - те же EMA20/50/200 + RSI + MACD + Stochastic + Volume; `data_get_study_values`
   - `data_get_ohlcv` с `summary: true` + `count: 60`
   - `capture_screenshot` → `TICKER_daily.png`
4. **Опционально**, если на графике есть pine-индикаторы (профайлер, supply/demand-зоны) — пройдись по `data_get_pine_lines` / `data_get_pine_labels` / `data_get_pine_boxes` для извлечения ключевых уровней.

Веди работу через скил `tradingview-mcp` для соблюдения правил context management (`summary: true`, `study_filter` где можно, и т.п.).

**Формат `technical.md`** (русский, две секции W и D + сводный диагноз):

```markdown
# Company (EXCHANGE:TICKER) — Технический анализ

**Дата:** YYYY-MM-DD
**Цена (last):** $XX.XX
**Контекст:** [1–2 строки о макро-фоне и связи с новостями]

---

## 1. Недельный таймфрейм (Weekly)

### Тренд
[направление, сила, слом / подтверждение]

### Ключевые уровни
| Тип | Уровень | Природа |
|---|---|---|

### Индикаторы Weekly
- **EMA20W / EMA50W / EMA200W** — позиция цены и наклон
- **RSI(14)W** — текущее значение, перекупленность/перепроданность
- **MACD W** — линия, сигнал, гистограмма, дивергенции
- **Stochastic %K/%D**
- **Volume** — относительный, climax-бары

---

## 2. Дневной таймфрейм (Daily)

[Аналогично Weekly, но детальнее по последним 5–10 свечам]

---

## 3. Сводный диагноз

| Фактор | Сигнал |
|---|---|

[2–3 предложения общего вывода: какая фаза, готов ли разворот, какие условия запуска]
```

Это самый важный артефакт. Его структура — копия `results/analysys/BSX/2026-05-15/report.md`.

### Шаг 5. Автоматическое создание алертов в TradingView

После того как `report.md` сформирован и приоритетный сценарий определён, **автоматически** создай набор алертов через `mcp__tradingview__alert_create`. Так пользователь получит уведомление от TradingView Desktop, как только цена достигнет триггера / стопа / целей, и не пропустит точку действия.

#### Принципы

- **Только приоритетный сценарий.** Алерты создаются ровно для одного направления — Long ИЛИ Short, не для обоих, иначе получим конфликтующие уведомления и шум.
- **Источник цифр — `report.md`.** Бери цены ровно те, что записаны в таблице приоритетного сценария (Trigger / Stop / T1 / T2 / T3). Не округляй, не пересчитывай.
- **Символ и таймфрейм.** К моменту шага активный символ уже выставлен (в Шаге 3). Перед алертами переключи таймфрейм на Daily (`chart_set_timeframe` → `"D"`), если он не Daily — алерты создаются под текущий ТФ.
- **Последовательность, не параллель.** `alert_create` управляет UI-диалогом TradingView (см. `feedback_create_alerts.md`). Дай каждому алерту завершиться до следующего — не вызывай несколько `alert_create` одним сообщением.
- **Между алертами — пауза.** Между вызовами `alert_create` подожди ~0.8–1 с (короткий sleep или просто следующий вызов после ответа предыдущего), чтобы UI успел закрыть диалог.

#### Набор алертов для Long-сценария (5 штук)

| # | Уровень | `price_condition` | Назначение | `message` (действие) |
|---|---|---|---|---|
| 1 | Trigger | `Crossing Up` | Активация сетапа — пробой ключевого уровня вверх | `TICKER: сигнал на покупку (лонг) — Trigger $XX.XX` |
| 2 | Stop | `Crossing Down` | Стоп-лосс — сценарий инвалидирован, выход | `TICKER: закрытие позиции по стопу (лонг) — Stop $XX.XX` |
| 3 | T1 | `Crossing Up` | Первая цель — частичная фиксация | `TICKER: закрытие позиции по T1 (лонг) — $XX.XX` |
| 4 | T2 | `Crossing Up` | Вторая цель | `TICKER: закрытие позиции по T2 (лонг) — $XX.XX` |
| 5 | T3 | `Crossing Up` | Третья цель (если указана) | `TICKER: закрытие позиции по T3 (лонг) — $XX.XX` |

#### Набор алертов для Short-сценария (5 штук) — направления зеркально

| # | Уровень | `price_condition` | `message` (действие) |
|---|---|---|---|
| 1 | Trigger | `Crossing Down` | `TICKER: сигнал на продажу (шорт) — Trigger $XX.XX` |
| 2 | Stop | `Crossing Up` | `TICKER: закрытие позиции по стопу (шорт) — Stop $XX.XX` |
| 3 | T1 | `Crossing Down` | `TICKER: закрытие позиции по T1 (шорт) — $XX.XX` |
| 4 | T2 | `Crossing Down` | `TICKER: закрытие позиции по T2 (шорт) — $XX.XX` |
| 5 | T3 | `Crossing Down` | `TICKER: закрытие позиции по T3 (шорт) — $XX.XX` |

#### Правила формирования `message`

Каждому алерту обязательно передавай параметр `message` с описанием действия — это критично, чтобы при срабатывании пользователь сразу понимал, что делать, не открывая `report.md`. Шаблон:

- **Trigger Long** → `"TICKER: сигнал на покупку (лонг) — Trigger $XX.XX"`
- **Trigger Short** → `"TICKER: сигнал на продажу (шорт) — Trigger $XX.XX"`
- **Stop (Long или Short)** → `"TICKER: закрытие позиции по стопу (лонг|шорт) — Stop $XX.XX"`
- **T1 / T2 / T3 (Long или Short)** → `"TICKER: закрытие позиции по TN (лонг|шорт) — $XX.XX"` (TN = T1, T2, T3 — название цели; направление — то, которое приоритетно)

Подставляй реальный тикер и реальную цену из таблицы приоритетного сценария в `report.md`. Не используй размытые формулировки («продать», «выйти») — всегда явное «закрытие позиции по T1 (лонг)» / «сигнал на покупку (лонг)», чтобы из одной строки уведомления было понятно: что за бумага, куда сейчас идёт цена и какое действие.

#### Если Entry — диапазон ($X.XX–$Y.YY)

Если в `report.md` Entry задан как диапазон (а не одна цена), отдельный Entry-алерт не нужен: Trigger уже покрывает активацию, а Stop — нижнюю границу инвалидации. Достаточно 5 алертов выше. Если Entry — одна конкретная цена, отличная от Trigger более чем на 1%, можешь добавить шестой алерт «Entry» с тем же условием, что и Trigger.

#### Вызов

```javascript
// Long-сценарий, Trigger
mcp__tradingview__alert_create({
  price: 63.50,
  price_condition: "Crossing Up",
  message: "BSX: сигнал на покупку (лонг) — Trigger $63.50"
})

// Long-сценарий, Stop
mcp__tradingview__alert_create({
  price: 60.00,
  price_condition: "Crossing Down",
  message: "BSX: закрытие позиции по стопу (лонг) — Stop $60.00"
})

// Long-сценарий, T1
mcp__tradingview__alert_create({
  price: 68.00,
  price_condition: "Crossing Up",
  message: "BSX: закрытие позиции по T1 (лонг) — $68.00"
})

// Short-сценарий, Trigger
mcp__tradingview__alert_create({
  price: 58.00,
  price_condition: "Crossing Down",
  message: "BSX: сигнал на продажу (шорт) — Trigger $58.00"
})
```

Параметр `message` **обязателен** для каждого алерта — он несёт описание действия (см. шаблоны выше). С 2026-05-16 `alert_create` корректно открывает popup поля Message в TradingView, заменяет дефолтный текст на твой и подтверждает Apply — итоговое сообщение сохраняется и в самом алерте (визуально в TradingView), и в REST-объекте.

#### Проверка

После всех `alert_create` вызови `mcp__tradingview__alert_list` один раз и сверь: для каждого ожидаемого уровня в списке должен быть алерт с правильной ценой и условием. Сохрани краткий результат для блока «Алерты» в `report.md` (см. ниже).

#### Дозапись блока «Алерты» в `report.md`

В самый конец `report.md` (после секции «Файлы») добавь блок подтверждения:

```markdown
## 🔔 Созданные алерты (приоритетный Long/Short-сценарий)

| Уровень | Цена | Условие | Действие при срабатывании | Статус |
|---|---|---|---|---|
| Trigger | $XX.XX | Crossing Up/Down | сигнал на покупку (лонг) / сигнал на продажу (шорт) | ✅ создан |
| Stop | $XX.XX | Crossing Down/Up | закрытие позиции по стопу (лонг/шорт) | ✅ создан |
| T1 | $XX.XX | Crossing Up/Down | закрытие позиции по T1 (лонг/шорт) | ✅ создан |
| T2 | $XX.XX | Crossing Up/Down | закрытие позиции по T2 (лонг/шорт) | ✅ создан |
| T3 | $XX.XX | Crossing Up/Down | закрытие позиции по T3 (лонг/шорт) | ✅ создан |

Алерты привязаны к символу `EXCHANGE:TICKER`, таймфрейм 1D. При срабатывании TradingView Desktop выдаст pop-up + звук, в тексте уведомления — действие из колонки выше.
```

Если какой-то алерт не создался — поставь статус `⚠️ не создан` и в `report.md` после таблицы укажи одной строкой, что нужно создать вручную.

#### Ошибки

- **`alert_create` не отвечает / диалог не открывается** → один retry с задержкой 2 с. Если повторно — пропусти этот конкретный уровень, продолжай с остальными, отметь `⚠️ не создан` в таблице и в emoji-summary.
- **`tv_health_check` падает (нет CDP-соединения)** → пропусти весь Шаг 5. В `report.md` в блоке «Алерты» напиши «TradingView Desktop недоступен — алерты не созданы, см. таблицы сценариев в Шаге 3 для ручной настройки». В emoji-summary укажи `🔔 алерты: ❌ TradingView недоступен`.
- **Нельзя использовать `alert_delete delete_all=true`** — это удалит ВСЕ алерты пользователя, не только те, что мы создали. Если в процессе нужно убрать конкретные тестовые алерты — через UI (см. `feedback_create_alerts.md`).

#### Когда НЕ создавать алерты

- Если итоговая рекомендация в `report.md` — **ДЕРЖАТЬ (HOLD)** без чёткого приоритетного сценария (нет активного сетапа). В этом случае пропусти Шаг 5, в `report.md` напиши «Алерты не созданы — нет приоритетного сетапа (HOLD)», в emoji-summary поставь `🔔 алерты: — (HOLD, нет триггера)`.
- Если в `report.md` оба сценария помечены как «не рекомендуется» — пропусти, аналогично HOLD.

### Шаг 6. Сохранение сигнала → `results/analysis/signals.md`

После того как `report.md` готов, **обязательно** дозапиши краткую строку сигнала в общий журнал `results/analysis/signals.md` (обрати внимание: путь `analysis`, не `analysys` — это общий журнал, не папка отчёта).

Если файла нет — создай его с заголовком. Каждый новый сигнал — это блок в конец файла:

```markdown
## YYYY-MM-DD — TICKER — 🟢 BUY / 🟡 HOLD / 🔴 SELL

- **Фаза:** [короткое описание сетапа, напр. «отскок от перепроданности», «брейкаут из консолидации»]
- **Entry:** $XX.XX–$XX.XX
- **Stop:** $XX.XX
- **T1 / T2 / T3:** $XX.XX / $XX.XX / $XX.XX
- **R/R:** X.X
- **Горизонт:** 1–2 нед / 1–3 мес
- **Главный риск:** [одна строка]
- **Алерты TradingView:** созданы / не созданы (и сколько штук)
- **Полный отчёт:** `results/analysys/TICKER/YYYY-MM-DD/report.md`
```

Этот журнал — единая точка для трекинга всех выданных рекомендаций. Не перезаписывай предыдущие записи, только append.

### Шаг 7. Краткий устный итог (вывод в чат)

После сохранения всех файлов выдай пользователю **компактный emoji-summary**, который читается за 45–60 секунд:

```
📊 TICKER — Company Name | $XX.XX | YYYY-MM-DD

🟢/🟡/🔴 РЕКОМЕНДАЦИЯ: ПОКУПАТЬ / ДЕРЖАТЬ / ПРОДАТЬ
Горизонт: краткосрочный 1–2 нед / среднесрочный 1–3 мес

📈 ТЕХНИКА (D):
• Тренд: восходящий/нисходящий/боковик
• RSI XX: перекуплен/нейтральный/перепродан
• MACD: бычий/медвежий
• Поддержка $XX.XX / Сопротивление $XX.XX

📰 НОВОСТИ: POSITIVE/NEGATIVE/MIXED
• [Ключевая новость 1]
• [Ключевая новость 2]

⚡ ЗА: [1–2 пункта] | ПРОТИВ: [1–2 пункта]

🎯 ПЛАН: Entry $XX.XX–$XX.XX, Stop $XX.XX, T1/T2/T3 $XX/$XX/$XX, R/R X.X

⚠️ Главный риск: [одна строка]

🔔 Алерты TradingView: ✅ создано N/5 (Trigger / Stop / T1 / T2 / T3) — или ❌ не созданы (причина)

📁 Полный отчёт: results/analysys/TICKER/DATE/report.md
```

Этот блок — **обязательная часть** ответа после всех `Write`-операций. Без него пользователь не получит мгновенной картины.

## Правила работы

1. **Краткость важнее полноты** — в `report.md` каждый пункт максимум 1–2 строки; детали — в `news.md`/`fundamental.md`/`technical.md`.
2. **Рекомендация обязательна** — никогда не заканчивай отчёт без чёткого ПОКУПАТЬ/ДЕРЖАТЬ/ПРОДАТЬ. Размытые «возможно стоит присмотреться» не считаются.
3. **Конкретные цифры** — все entry/stop/T1/T2/T3 указаны как реальные цены, а не «около поддержки». То же для уровней индикаторов: «RSI 28», а не «RSI низкий».
4. **`summary: true` для OHLCV** — `data_get_ohlcv` всегда вызывай с `summary: true`, иначе зальёшь контекст сотнями свечей.
5. **Не вызывай `pine_get_source`** — этот тул может вернуть 200KB+ Pine-кода; для одной аналитики он не нужен.
6. **`chart_get_state` — один раз в начале** каждого таймфрейма. Сохрани entity ID индикаторов и используй их в последующих `indicator_set_inputs` / `data_get_study_values`.
7. **Полные имена индикаторов** при добавлении через `chart_manage_indicator`: `"Relative Strength Index"`, `"Moving Average Exponential"`, `"MACD"`, `"Stochastic"`, `"Volume"` — короткие имена («RSI», «EMA») молча не сработают.
8. **Язык** — итоговый чат-summary и `report.md`/`fundamental.md`/`technical.md` строго на русском (правило `.claude/rules/language.md`). `news.md` оставляем на английском (методология `market-news-analyst`).

## Обработка ошибок

- **Тикер не найден в TradingView** → попробуй явный префикс биржи: `NASDAQ:TICKER`, `NYSE:TICKER`, `MOEX:TICKER`, `AMEX:TICKER`. Если не помогло — `symbol_search` для поиска корректного формата.
- **Нет данных по индикаторам** (`data_get_study_values` пустой) → проверь, что индикатор реально добавлен (`chart_get_state`), и что нужный таймфрейм активен. Если индикатор не загрузился — продолжай с OHLCV + скриншотом, отметь ограничение в `technical.md`.
- **TradingView недоступен** (нет CDP-соединения, `tv_health_check` падает) → не блокируй задачу. Выполни шаги 1 (новости) и 2 (фундаментал), пропусти 3. В `report.md` явно укажи: «Технический анализ недоступен — TradingView не подключён», и в emoji-summary поставь рекомендацию ДЕРЖАТЬ, если новости + фундаментал не дают однозначного сигнала.
- **`market-news-analyst` недоступен / `WebSearch` rate-limited** → собери минимум 3–4 новости прямыми `WebFetch` к Yahoo Finance / investor relations компании. В `news.md` пометь «частичные данные».
- **Данных недостаточно для уверенной рекомендации** → дай рекомендацию ДЕРЖАТЬ с явным пояснением, какого слоя данных не хватает, и какое событие/уровень снимет неопределённость.

## Параллелизация

Шаги 1, 2 и 3 **независимы** и могут выполняться параллельно:

- Шаг 1 (новости) → отдельный подагент `general-purpose` если нужно много `WebSearch` за раз; иначе inline
- Шаг 2 (фундаментал) → подагент `general-purpose` для сбора данных с веба, или inline через `WebSearch`/`WebFetch`
- Шаг 3 (техника) → **inline**, потому что использует mcp__tradingview__* (один CDP-канал, нельзя из подагента, который не имеет доступа к этому MCP)

Делай все три ветки в **одном сообщении** (несколько tool calls одновременно). Шаг 4 (`report.md`) делается **после** трёх предыдущих. Шаг 5 (алерты) — **строго последовательно после** Шага 4, потому что цены берутся из готового `report.md` и каждый `alert_create` управляет UI-диалогом TradingView (нельзя параллельно).

Или использовать `cp` + `rm`, если важно сохранить исходник. Делай это сразу после каждого capture_screenshot.

## Чек-лист готовности

Перед тем как сказать пользователю, что отчёт готов, проверь:

- [ ] Оба скриншота (weekly, daily) лежат там же под правильными именами
- [ ] В `report.md` есть **обе** таблицы сценариев (Long, Short) с конкретными числами entry/stop/T1/T2/T3
- [ ] В `report.md` явно отмечено, какой сетап в приоритете
- [ ] Указан главный риск, который инвалидирует основной сценарий
- [ ] R/R приоритетного сценария посчитан и упомянут
- [ ] Сигнал дозаписан в `results/analysis/signals.md` (BUY/HOLD/SELL + entry/stop/T1-T3 + ссылка на полный отчёт)
- [ ] Алерты в TradingView созданы для приоритетного сценария (Trigger / Stop / T1 / T2 / T3) ИЛИ явно указано почему пропущено (HOLD / TradingView недоступен)
- [ ] Каждому алерту передан `message` с описанием действия по шаблону: «сигнал на покупку (лонг)» / «сигнал на продажу (шорт)» / «закрытие позиции по TN (лонг|шорт)»
- [ ] В `report.md` в конце есть блок «🔔 Созданные алерты» с таблицей статусов и колонкой «Действие при срабатывании»
- [ ] В чат выдан компактный emoji-summary с рекомендацией ПОКУПАТЬ/ДЕРЖАТЬ/ПРОДАТЬ и строкой «🔔 Алерты»

После проверки отдай пользователю:
1. Компактный emoji-summary (Шаг 6) — это первое, что он увидит
2. Путь к `report.md` (главный файл с деталями)

## Что НЕ делать

- Не делай отчёт без скриншотов — они дают пользователю мгновенный визуальный контекст.
- Не пиши «нужны дополнительные данные» в report.md — если данных не хватает, добери их (доп `WebSearch`, доп `data_get_*`), не оставляй пробелы.
- Не давай размытые точки входа («где-то около поддержки») — всегда конкретные числа.
- Не пропускай stop-loss — каждый сценарий обязан иметь явный инвалидирующий уровень.
- Не используй full-region скриншоты — только `chart`, иначе в png попадает лишний UI и фотография становится бесполезной для архива.
- Не вызывай `pine_get_source` — слишком тяжёлый ответ, для аналитики тикера не нужен.
- Не вызывай `data_get_ohlcv` без `summary: true` — это разрушит контекст.
- Не пропускай дозапись в `results/analysis/signals.md` — без неё журнал сигналов рассинхронизируется с отчётами.
- Не вызывай несколько `alert_create` параллельно — каждый управляет UI-диалогом, параллель ломает state.
- Не создавай алерты на оба сценария сразу (Long + Short) — только на приоритетный, иначе уведомления будут конфликтовать.
- Не вызывай `alert_create` без параметра `message` — без описания действия пользователь при срабатывании не поймёт, что делать (покупать / продавать / закрывать). Шаблоны действий — в Шаге 5.
- Не вызывай `alert_delete delete_all=true` для уборки — это снесёт ВСЕ алерты пользователя, включая чужие.
- Не заканчивай ответ без emoji-summary (Шаг 7) — пользователь должен увидеть рекомендацию мгновенно, не открывая `report.md`.
