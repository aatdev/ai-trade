# daily-buy-scan — ежедневный конвейер поиска кандидатов на покупку

## Назначение

Один повторяемый дневной прогон, который связывает уже установленные скиллы в сквозной воркфлоу свинг-трейдера (см. `results/trading-skills-guide.md`):

```
uptrend-analyzer (гейт рынка)
        ↓
vcp-screener + canslim-screener  → объединённый шорт-лист (dedup)
        ↓
ticker-analysis × ТОП-5          → report.md + запись в signals.md по каждому
        ↓
add_to_watchlist.mjs             → BUY-кандидаты в watchlist «t»
        ↓
signals-alerts (sync)            → 5 алертов (Trigger/Stop/T1/T2/T3) на каждый BUY
        ↓
итоговый отчёт                   → results/analysis/daily-scan/YYYY-MM-DD.md
```

**Этот скилл — оркестратор.** Он не дублирует логику скрининга, анализа или постановки алертов — он вызывает соответствующие скиллы/скрипты по очереди и сводит результат. Тяжёлую работу делают они.

## Когда триггериться

- «запусти ежедневный скан», «утренний прогон», «daily buy scan», «/daily-buy-scan»
- «найди кандидатов на покупку и поставь алерты», «что купить сегодня — прогони скринеры»
- «обнови watchlist t свежими сетапами», «прогони VCP+CANSLIM и разбери топ»

Не триггериться, если:
- запрос про разбор ОДНОГО конкретного тикера → это `ticker-analysis`;
- запрос только про скрининг без анализа/алертов → это напрямую `vcp-screener` / `canslim-screener`;
- запрос только про синхронизацию алертов из готового журнала → это `signals-alerts`.

## Параметры прогона (дефолты)

| Параметр | Дефолт | Описание |
|---|---|---|
| Гейт рынка | **вкл** | `uptrend-analyzer` перед скринингом; низкий балл → предупреждение и сокращение/пропуск набора |
| Скринеры | **VCP + CANSLIM** | оба, объединяем шорт-листы, dedup по тикеру |
| Глубина анализа | **топ-5** | сколько кандидатов прогнать через полный `ticker-analysis` |
| Watchlist | **«t»** | куда добавлять BUY-кандидатов (см. шаг 4) |
| Алерты | **вкл** | `signals-alerts sync` по свежим BUY-сигналам |
| Telegram | **выкл** | отправка отчёта только по явной просьбе («+telegram») |

Пользователь может переопределить любой словами: «без гейта», «только VCP», «топ-3», «не ставь алерты», «+telegram».

## Алгоритм работы

### Шаг 0. Проверка окружения

Запусти `mcp__tradingview__tv_health_check`. Если падает:

> ❌ TradingView Desktop недоступен. Запусти `tv launch` или `./scripts/launch_tv_debug_mac.sh` и повтори.

…и остановись. Скрининг на свечах живого графика, добавление в watchlist и алерты — всё требует живого CDP.

**Освежи кэш метрик (ускоряет шаги 2–3).** Скринеры VCP/CANSLIM и ticker-analysis сначала читают `state/metrics/TICKER/` (свечи + индикаторы + фундаментал) и переключают чарт только на устаревшее (>2 дней). Перед прогоном обнови снапшоты:

```bash
node scripts/collect_russell.js --source snp500 --update   # S&P 500; Russell: без --source
```

Это разовый проход; после него полный скан по свежему кэшу почти не трогает живой график. Если кэш свежий с прошлого запуска — шаг можно пропустить.

### Шаг 1. Гейт рынка (uptrend-analyzer)

Вызови скилл **uptrend-analyzer** → получи композитный балл 0–100 и фазу среды.

- **Балл ≥ 60 (благоприятно)** → продолжай в полном размере.
- **40–59 (смешанно)** → продолжай, но в отчёте пометь «сократить размер позиций»; в шаге 3 можно ужать глубину.
- **< 40 (неблагоприятно)** → **спроси пользователя**, продолжать ли скан, или зафиксировать «сегодня в кэше». По умолчанию — продолжаем скрининг (это бесплатно), но в финальном отчёте крупно выводим предупреждение и помечаем все сигналы как «watch-only, не набирать против рынка».

Балл и фазу всегда клади в шапку финального отчёта — это контекст для всех сигналов.

### Шаг 2. Скрининг → объединённый шорт-лист

Запусти **оба** скринера (если пользователь не сузил):

1. **vcp-screener** — на свечах живого TradingView (обход FMP). Свинговые пробои тайтовых баз.
2. **canslim-screener** — растущие лидеры рынка.

Оба возвращают ранжированные списки со скором. Действия:

- Возьми top-кандидатов каждого скринера, **объедини в один список, dedup по тикеру**. Если тикер вышел в обоих — это сильный сигнал; в объединённом ранге подними его выше (например, сумма/максимум нормированных скоров + бонус за «в обоих»).
- Отбрось тикеры с очевидно медвежьим/Stage-4 профилем (скринеры лонговые, но перепроверь направление по скору).
- Отрежь шорт-лист до глубины анализа (**топ-5** по умолчанию).

В отчёте сохрани и полный объединённый список (с пометкой источника VCP/CANSLIM/оба), и отобранный топ-5.

> Скринеры пишут свои промежуточные JSON/MD в свои каталоги `scripts/`. Это нормально — финальный артефакт собирает этот скилл.

### Шаг 3. Глубокий разбор топ-5 (ticker-analysis)

Для **каждого** из топ-5 вызови скилл **ticker-analysis** (он сам делает новости + фундаментал + техника + график, сохраняет `results/analysis/TICKER/DATE/` и **обязательно** дозаписывает блок в `results/analysis/signals.md` по строгому формату — Шаги 5.1 prune → 5.2 append внутри ticker-analysis).

Важно:
- Анализируй кандидатов **последовательно** (каждый держит живой график; параллельные прогоны ломают состояние графика и UI-диалоги).
- Нас интересуют **BUY (🟢)** сигналы — это и есть «кандидаты на покупку». HOLD/WAIT и SELL фиксируй в отчёте, но **в watchlist «t» и в алерты они не идут** (watchlist «t» — список покупки).
- ticker-analysis сам **не ставит алерты** — это сделает шаг 5. Не проси его об этом здесь.

После шага 3 в `signals.md` лежат свежие, актуальные блоки по всем разобранным тикерам.

### Шаг 4. Добавление BUY-кандидатов в watchlist «t»

Собери список тикеров, у которых сигнал = **BUY (🟢 / лонг с приоритетным Long-сценарием)**. Добавь их в watchlist «t» одним вызовом скрипта (один CDP-сеанс на весь батч):

```bash
node .claude/skills/daily-buy-scan/scripts/add_to_watchlist.mjs --name t --tickers NVDA,AVGO,PLTR
```

Или передать тикеры через stdin (JSON-массив):

```bash
echo '["NVDA","AVGO","PLTR"]' | node .claude/skills/daily-buy-scan/scripts/add_to_watchlist.mjs --name t
```

Скрипт:
1. health-check; открывает правую панель; **переключается на список «t»** по имени и **проверяет, что активен именно он** (читает заголовок). Если активен другой список — НЕ добавляет ничего (exit 3), чтобы не засорять чужой список.
2. Дедуп: тикеры, уже присутствующие в «t», пропускает (`already`).
3. Добавляет недостающие, по одному, с паузами.

Флаги: `--create` (создать список «t», если его нет), `--dry-run` (только проверить переключение, ничего не добавлять).

Захвати stdout (JSON-отчёт `{ added, already, errors, summary }`) для финальной таблицы. Если `error` про несовпадение активного списка — вынеси это в отчёт как ⚠️ и предложи пользователю проверить имя списка вручную.

> Почему отдельный скрипт, а не `mcp__tradingview__watchlist_add`: штатный `watchlist_add` пишет в **активный** список и добавляет по одному символу. Скрипт сперва гарантирует, что активен именно «t», и батчит добавление в одном соединении.

### Шаг 5. Алерты (signals-alerts sync)

По свежим BUY-сигналам поставь алерты. Поскольку шаг 3 уже записал их в `results/analysis/signals.md`, просто синхронизируй — **только по тикерам-кандидатам этого прогона** (чтобы не трогать чужие сигналы в журнале):

```bash
# 5.1 — план только по BUY-тикерам прогона
node .claude/skills/signals-alerts/scripts/parse_signals.mjs --tickers NVDA,AVGO,PLTR \
  > ./tmp/daily_scan_plan_$(date +%Y%m%d_%H%M%S).json

# 5.2 — diff-удаление устаревших «наших» алертов по этим тикерам
node .claude/skills/signals-alerts/scripts/delete_alerts.mjs --keep-from-plan --file ./tmp/daily_scan_plan_*.json

# 5.3 — создать недостающие (дедуп по message пропустит существующие)
cat ./tmp/daily_scan_plan_*.json | node .claude/skills/signals-alerts/scripts/create_alerts.mjs
```

Это и есть `signals-alerts` в режиме **sync (diff)**, но с фильтром по тикерам прогона. Алгоритм, формат плана и правила — см. `.claude/skills/signals-alerts/SKILL.md` (его и читай, если нужны детали). 5 алертов на сигнал: Trigger / Stop / T1 / T2 / T3.

Команды выполняй **последовательно** (каждая держит CDP-сеанс). Захвати JSON-отчёты delete и create для финальной таблицы.

> ⚠️ Штатный `alert_create` подломан (хэшированные CSS-классы) — `signals-alerts` обходит это через `ui_click` + CDP-keystrokes. Не пытайся ставить алерты напрямую через `mcp__tradingview__alert_create`.

### Шаг 6. Итоговый отчёт

Собери `results/analysis/daily-scan/YYYY-MM-DD.md` по шаблону ниже. Это **финальный артефакт** (в `results/`, не в `tmp/`).

```markdown
# Daily Buy Scan — YYYY-MM-DD

## 🌍 Рыночная среда
- **Балл (uptrend-analyzer):** NN/100 — <фаза> (<благоприятно/смешанно/неблагоприятно>)
- **Вывод по размеру позиций:** <полный / сократить / кэш>
<если балл < 40 — крупный блок ⚠️ «торговать против рынка не рекомендуется»>

## 🔍 Скрининг
- **VCP:** N кандидатов | **CANSLIM:** M кандидатов | **в обоих:** K
- Объединённый шорт-лист (top): <таблица Ticker | Источник | Скор>
- **В глубокий разбор (топ-5):** TICKER1, TICKER2, …

## 📊 Кандидаты (ticker-analysis)
| Ticker | Сигнал | Фаза | Trigger | Stop | T1/T2/T3 | R/R | Отчёт |
|---|---|---|---|---|---|---|---|
| NVDA | 🟢 BUY | … | … | … | … | … | [report](TICKER/DATE/report.md) |
| … | 🟡 HOLD | … | — | — | — | — | … |

## 📋 Watchlist «t»
- Добавлено: NVDA, AVGO  (already: PLTR)  | ошибок: 0

## 🔔 Алерты
| Ticker | Создано | Удалено | Без изм. | Статус |
|---|---|---|---|---|
| NVDA | 5 | 0 | 0 | ✅ |
| AVGO | 5 | 0 | 0 | ✅ |

## 🧭 План на день
- Топ-приоритет: <тикер + одна строка почему>
- Наблюдать: <тикеры на подтверждении триггера>
- Итог: разобрано X, BUY Y, в watchlist Z, алертов A.
```

В чат выведи компактную сводку (среда + таблица кандидатов + что добавлено/проставлено) и ссылку на сохранённый файл отчёта.

### Шаг 7 (опционально). Telegram

Только если пользователь явно попросил («+telegram», «пришли в телегу»): вызови скилл **send-telegram** с готовым `results/analysis/daily-scan/YYYY-MM-DD.md`.

## Жёсткие правила

- **Не дублируй логику** скрининга / анализа / алертов — вызывай скиллы и скрипты. Этот скилл только оркеструет и сводит отчёт.
- **Последовательность строгая:** гейт → скрининг → анализ (он пишет `signals.md`) → watchlist → алерты (читают `signals.md`) → отчёт. Алерты **после** записи в `signals.md`, иначе `parse_signals.mjs` увидит старые уровни или ничего.
- **Скрипты — последовательно, не параллельно.** Каждый держит свой CDP-сеанс; конкурентные прогоны ломают UI-диалоги TradingView.
- **В watchlist «t» и в алерты — только BUY (🟢).** HOLD/WAIT/SELL остаются в отчёте и `signals.md`, но не идут в список покупки и не получают алертов в этом прогоне.
- **Алерты — sync с фильтром по тикерам прогона** (`--tickers`/`--keep-from-plan`), чтобы не трогать чужие сигналы в журнале. **Никогда** не вызывай `delete_all: true`.
- **Не пиши в `signals.md` сам** — это делает `ticker-analysis` (шаг 3). Этот скилл журнал только читает (через `parse_signals.mjs`).
- **Финальный отчёт → `results/analysis/daily-scan/`**, временные планы → `./tmp/`.
- **Telegram — только по явной просьбе.**

## Примеры

- «запусти ежедневный скан» → полный конвейер с дефолтами (гейт, VCP+CANSLIM, топ-5, watchlist «t», алерты).
